================================================================================
1. CONCEPTO GENERAL
================================================================================

El sistema de notificaciones de flujo permite que el personal reciba alertas
en tiempo real dentro de la aplicación (campana de notificaciones) cuando un
flujo de ventas avanza a un paso específico.

Ejemplo de uso real:
  "Cuando un flujo pasa a Revisión de Inventario, notificar a todos los
   usuarios con rol Auditoria y Logistica para que sepan que deben revisar."

Las notificaciones son:
  - Internas (canal "database" de Laravel Notifications)
  - Se guardan en la tabla "notifications" de la BD
  - Aparecen en el ícono de campana del header de la aplicación
  - No son emails ni SMS — son notificaciones in-app

3. CONTROL GLOBAL ON/OFF
================================================================================

El sistema tiene un interruptor maestro que activa o desactiva TODAS las
notificaciones de flujo de una sola vez.

IMPLEMENTACIÓN (patrón Cache-Aside):
  ─ Fuente de verdad: tabla configuracion_sistema
      clave='notificaciones_sistema_activo', valor='1' (activo) o '0' (inactivo)

  ─ Acelerador: Laravel Cache
      clave='notificaciones_sistema_activo'
      Guardado con Cache::forever() al cambiar el valor

  ─ Regla de lectura (Cache-Aside):
      1. Se lee de caché (< 0.1 ms)
      2. Si la caché no existe (tras cache:clear / restart):
         → Se lee de BD
         → Se repobla la caché automáticamente (TTL: 1 hora)
         → Se retorna el valor de BD
      Esto garantiza que un cache:clear NO desactiva las notificaciones.

DÓNDE SE CAMBIA:
  Pantalla: /configuracion/notificaciones
  Componente: App\Http\Livewire\Configuracion\ConfiguracionNotificaciones
  Método: toggleSistema()
    → Escribe en BD primero
    → Luego actualiza caché

ESTADO ACTUAL: ACTIVO (valor='1' en BD)

DÓNDE SE VERIFICA (Listener):
  $sistemaActivo = (bool)(int) Cache::remember(
      'notificaciones_sistema_activo',
      3600,
      fn () => DB::table('configuracion_sistema')
          ->where('clave', 'notificaciones_sistema_activo')
          ->value('valor') ?? '0'
  );
  if (!$sistemaActivo) return; // no notificar

4. TABLA DE CONFIGURACIÓN DE REGLAS (notificacion_flujo_config)
================================================================================

Esta tabla define las reglas: "para el paso X del flujo, notificar al rol Y".

ESTRUCTURA:
────────────────────────────────────────────────────────────────────────────────
Columna           | Tipo     | Descripción
------------------+----------+--------------------------------------------------
id                | bigint   | PK
tipo_tramite_id   | bigint   | Paso del flujo que dispara la notificación
                  |          | (FK a tipos_tramites.id)
rol_id            | bigint   | Rol que recibe la notificación
                  |          | NULL si se usa vía área (deshabilitada)
area_id           | bigint   | Área que recibe la notificación
                  |          | NULL si se usa vía rol (activa)
nivel_max_id      | bigint   | Nivel máximo del área a notificar (vía área)
                  |          | NULL actualmente
escalar_activo    | tinyint  | 0=sin escalación, 1=con escalación
                  |          | (no implementado todavía)
escalar_horas     | int      | Horas antes de escalar
                  |          | NULL actualmente
escalar_nivel_id  | bigint   | Nivel al que se escala
                  |          | NULL actualmente
activo            | tinyint  | 1=regla activa, 0=regla deshabilitada
created_at        | timestamp|
updated_at        | timestamp|

REGLA DE RESOLUCIÓN:
  Si rol_id está definido → se notifica a TODOS los usuarios activos con ese rol
  Si area_id está definido (y rol_id = NULL) → modo área (deshabilitado por ahora)
  Si ninguno está definido → no se notifica a nadie

5. VÍA POR ROL (ACTIVA Y EN USO)
================================================================================

Esta es la vía habilitada actualmente. Funciona así:

  1. La regla tiene rol_id definido (no NULL)
  2. El Listener llama a config->resolverUsuariosDestino()
  3. El método ejecuta:
       User::where('estado_id', 1)
           ->where('rol_id', $this->rol_id)
           ->get()
  4. Obtiene todos los usuarios ACTIVOS con ese rol
  5. Les envía la notificación usando Notification::send()

CARACTERÍSTICA: si en el futuro se agregan usuarios a ese rol, automáticamente
empezarán a recibir las notificaciones sin cambiar ninguna configuración.

DEDUPLICACIÓN:
  El Listener deduplica por usuario: si dos reglas apuntan al mismo usuario,
  solo recibe UNA notificación (using ->unique('id') en la colección).

8. FLUJO TÉCNICO COMPLETO: DE EVENTO A NOTIFICACIÓN EN PANTALLA
================================================================================

PASO 1 — El código del flujo dispara el evento:

  event(new FlujoAvanzadoEvent(
      $this->flujoId,       // ej: 50
      9,                    // tipo_tramite_id = Revisión de Inventario
      [
          'cliente'    => 'DISTRIBUIDORA UNIVERSAL',
          'monto'      => 15000.00,
          'referencia' => 'Prefactura #123',
      ]
  ));

PASO 2 — FlujoAvanzadoEvent almacena los datos:
  public int   $flujoId
  public int   $tipoTramiteId
  public array $contexto

PASO 3 — Laravel despacha al Listener registrado:
  NotificarPersonalFlujoListener::handle(FlujoAvanzadoEvent $event)

PASO 4 — El Listener verifica el interruptor global (Cache-Aside):
  Si notificaciones_sistema_activo = false → DETIENE (sin notificar)

PASO 5 — Busca reglas activas para tipo_tramite_id=9:
  NotificacionFlujoConfig::activos()->paraTramite(9)->get()
  Scopes:
    activos()      → where('activo', true)
    paraTramite(9) → where('tipo_tramite_id', 9)

PASO 6 — Para cada regla, resuelve usuarios destino:
  config->resolverUsuariosDestino()
  En la regla id=2: rol_id=1 (Administrador)
  → User::where('estado_id', 1)->where('rol_id', 1)->get()
  → Devuelve todos los Administradores activos

PASO 7 — Deduplica usuarios:
  $usuariosUnicos = $usuariosNotificados->unique('id')

PASO 8 — Envía la notificación:
  Notification::send($usuariosUnicos, new FlujoNotification(50, 9, $contexto))

PASO 9 — FlujoNotification arma el payload:

  TRAMITE_CONFIG[9] = [
      'titulo' => 'Revisión de Inventario',
      'icono'  => 'fa-boxes',
      'color'  => '#FF9800',
      'url'    => '/flujo/revicion_inventario',
  ]

  toDatabase() retorna:
  {
    "tipo_tramite_id": 9,
    "titulo": "Revisión de Inventario",
    "mensaje": "Flujo #50 · DISTRIBUIDORA UNIVERSAL | L 15,000.00 · Prefactura #123",
    "icono": "fa-boxes",
    "color": "#FF9800",
    "url": "/flujo/revicion_inventario?flujo_id=50",
    "leida": false,
    "flujo_id": 50
  }

PASO 10 — Laravel escribe en la tabla notifications:
  Una fila por usuario con el payload serializado en data (JSON)

PASO 11 — El header de la app lee las notificaciones no leídas:
  Componente de campana → muestra el badge con el conteo
  Al hacer clic → lista las notificaciones con título, mensaje y enlace

PASO 12 — El usuario hace clic en una notificación de flujo de ventas:
  La campana renderiza:
    <a href="/flujo/ventas/historico?flujo_id=50"
       wire:click="marcarLeida('...')">
  Comportamiento:
    a) marcarLeida() marca la notificación como leída (AJAX)
    b) El navegador sigue el href hacia /flujo/ventas/historico?flujo_id=50

PASO 13 — ListarVentas::mount() detecta el parámetro flujo_id:
  Archivo: app/Http/Livewire/Flujo/ListarVentas.php
  Código añadido en mount():
    if ($flujoId = (int) request()->get('flujo_id')) {
        $this->abrirFlujoDesdeRegistro($flujoId);
    }
  Cadena de resolución:
    abrirFlujoDesdeRegistro(50)
      → DB::table('flujo')->where('id',50)->value('identificacion') → pedido_id
      → emit('abrirFlujoPedido', $pedidoId)
      → ModalFlujoPedido escucha el evento y abre el modal del flujo correspondiente
  Resultado: el modal del flujo se abre automáticamente al cargar la página.

12. CÓMO CONSULTAR NOTIFICACIONES EN BD
================================================================================

Ver todas las notificaciones no leídas de un usuario (id=73):

  SELECT
    n.id,
    n.created_at,
    JSON_EXTRACT(n.data, '$.titulo')   AS titulo,
    JSON_EXTRACT(n.data, '$.mensaje')  AS mensaje,
    JSON_EXTRACT(n.data, '$.url')      AS url,
    JSON_EXTRACT(n.data, '$.flujo_id') AS flujo_id
  FROM notifications n
  WHERE n.notifiable_id   = 73
    AND n.notifiable_type = 'App\\Models\\User'
    AND n.read_at IS NULL
  ORDER BY n.created_at DESC;

Ver cuántas notificaciones no leídas tiene cada usuario:

  SELECT
    u.name,
    COUNT(n.id) AS no_leidas
  FROM notifications n
  INNER JOIN users u ON u.id = n.notifiable_id
  WHERE n.notifiable_type = 'App\\Models\\User'
    AND n.read_at IS NULL
  GROUP BY u.id, u.name
  ORDER BY no_leidas DESC;

Ver todas las notificaciones de un flujo específico (flujo_id=50):

  SELECT
    u.name              AS destinatario,
    n.read_at           AS leida_en,
    JSON_EXTRACT(n.data, '$.titulo')  AS titulo,
    JSON_EXTRACT(n.data, '$.mensaje') AS mensaje,
    n.created_at
  FROM notifications n
  INNER JOIN users u ON u.id = n.notifiable_id
  WHERE n.notifiable_type = 'App\\Models\\User'
    AND JSON_EXTRACT(n.data, '$.flujo_id') = 50
  ORDER BY n.created_at ASC;

Marcar todas como leídas para un usuario (vía código):
  Auth::user()->unreadNotifications->markAsRead();

Contar no leídas (vía código):
  Auth::user()->unreadNotifications()->count();

CÓMO AGREGAR UNA NUEVA REGLA DE NOTIFICACIÓN
================================================================================

Ejemplo: notificar al rol "Créditos y Cobros" (rol_id=4) cuando llegue una
Revisión de Crédito (tipo_tramite_id=10).

OPCIÓN A — Desde la pantalla (recomendado):
  1. Ir a /configuracion/notificaciones
  2. Clic en "Nueva regla"
  3. Seleccionar paso: "Rev. Crédito"
  4. Seleccionar rol: "Créditos y Cobros"  ← único tipo de destino disponible por ahora
  5. Guardar

OPCIÓN B — Directamente en BD:
  INSERT INTO notificacion_flujo_config
    (tipo_tramite_id, rol_id, area_id, escalar_activo, activo, created_at, updated_at)
  VALUES
    (10, 4, NULL, 0, 1, NOW(), NOW());

CÓMO AGREGAR UN NUEVO TIPO DE PASO AL CATÁLOGO (para que aparezca en el dropdown):
  1. Insertar en tipos_tramites (nombre, estado='activo', estado_id=1)
  2. Insertar en flujo_etapas (tipo_tramite_id, nombre_display, icono, orden, activo=1)
  3. Agregar entrada en TRAMITE_CONFIG dentro de FlujoNotification.php
  4. El caché flujo_etapas_activas se invalida automáticamente (modelo FlujoEtapa tiene
     booted() con Cache::forget en save/delete, o hacerlo manual con Cache::forget)
