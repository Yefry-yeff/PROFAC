## 3. Bug: Items del Menú Lateral Invisibles al Navegar

### Síntoma
Al navegar entre páginas, los sub-items del menú lateral aparecían colapsados o invisibles. El menú expandía el grupo correcto pero los links no se veían.

### Diagnóstico (inspección con Playwright)

Se inspeccionó el DOM y estilos computados directamente en el navegador:

- `ul.nav-second-level.collapse.in` → `height: 164px`, `display: block` — **correctamente expandido en el DOM**
- `li > a` hijos → `visibility: collapse` — **invisibles a pesar de tener altura y color correctos**

Se buscó la regla CSS causante y se encontró en `css/app.css`:

```css
.collapse {
    visibility: collapse;   /* ← Tailwind CSS utility */
}
```

### Causa raíz — Colisión Tailwind CSS vs Bootstrap

Tailwind CSS genera una clase utilitaria `.collapse` que aplica `visibility: collapse`. Bootstrap 3 también usa la clase `.collapse` pero para controlar visibilidad de submenús via `display`. Al compilar ambos en `app.css`, la regla de Tailwind sobreescribía el comportamiento del sidebar.

La herencia CSS hacía que todos los hijos del `ul.collapse` (incluyendo los `<li>` y `<a>`) recibieran `visibility: collapse`, dejándolos invisibles aunque ocuparan espacio en el DOM.

### Fix aplicado

**Archivo:** `resources/views/navigation-menu.blade.php`

Se agregó un override CSS específico para el sidebar antes de cualquier otra regla del layout:

```css
/* Fix: colisión Tailwind .collapse (visibility:collapse) vs Bootstrap .collapse */
#side-menu .nav-second-level,
#side-menu .nav-second-level li,
#side-menu .nav-second-level li a {
    visibility: visible !important;
}
```

### Otros cambios relacionados al menú

**Archivo:** `resources/views/partials/menu-dinamico.blade.php`
- Se agregó lógica para aplicar clase `active` en el `<li>` del grupo correcto al cargar la página (con matching wildcard de URL).
- Se agrega clase `in` al `ul.nav-second-level` del grupo activo para que MetisMenu lo mantenga expandido sin necesidad de JS extra.

**Archivo:** `resources/views/navigation-menu.blade.php`
- Se eliminó código JS que llamaba `li.classList.remove('active')` en todos los `#side-menu > li` al cerrar el sidebar móvil. Esa línea estaba borrando el estado de MetisMenu y causando que al reabrir el sidebar los submenús aparecieran colapsados.

## Lecciones Aprendidas

1. **No correr `php artisan migrate` sin revisar qué migraciones están pendientes.** En producción hay muchas migraciones de funcionalidades en desarrollo que pueden crear o modificar tablas de forma no deseada.

2. **Colisión Tailwind + Bootstrap:** El nombre de clase `collapse` existe en ambos con comportamientos distintos. Con Tailwind v3+, la solución limpia es configurar un prefijo en `tailwind.config.js` (`prefix: 'tw-'`). La solución rápida aplicada hoy es un override `visibility: visible !important` en el selector específico del sidebar.

3. **MetisMenu** lee la clase `active` del `<li>` renderizado por el servidor para decidir qué submenús mantener expandidos. No regenera ese estado dinámicamente — si el JS borra las clases `active`, MetisMenu no las puede recuperar.

4. **`visibility: collapse`** es diferente a `display: none` — el elemento **ocupa espacio** en el DOM y tiene altura, pero es completamente invisible. Es fácil de confundir con un problema de altura o de MetisMenu.
